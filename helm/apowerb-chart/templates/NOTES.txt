What is left to check, in this order:

  1. The pods are ready:
       kubectl -n {{ include "apowerb.namespace" . }} get pods
{{- if and .Values.th2etl.enabled .Values.th2etl.seed.enabled }}
       kubectl -n {{ include "apowerb.namespace" . }} logs job/{{ include "apowerb.th2etl.fullname" . }}-seed
{{- end }}

  2. Reach the interface:
{{- if .Values.ingress.enabled }}
       http{{ if .Values.ingress.tlsEnabled }}s{{ end }}://{{ .Values.ingress.host }}
  {{- if not .Values.ingress.tlsEnabled }}

  ⚠️  ingress.tlsEnabled=false: the interface is served in clear, and the
      address verification links will go out over http://. Enable it once
      cert-manager is in place (annotation `cert-manager.io/cluster-issuer`).
  {{- end }}
{{- else if eq .Values.service.frontend.type "LoadBalancer" }}
       kubectl -n {{ include "apowerb.namespace" . }} get svc {{ include "apowerb.frontend.fullname" . }}
       (the external address shows once the provider has assigned the IP)
{{- else }}
       kubectl -n {{ include "apowerb.namespace" . }} port-forward svc/{{ include "apowerb.frontend.fullname" . }} 3000:{{ .Values.service.frontend.port }}

       Nothing is exposed outside the cluster: enable `ingress.enabled`, or
       set `service.frontend.type` to LoadBalancer.
{{- end }}

  3. The interface itself says what is not configured:
     sign in as an administrator, then Admin → Configuration.
     The badge in the sidebar counts what is still missing.
{{- if not .Values.th2etl.apiKey }}

  ⚠️  th2etl.apiKey is empty: the backend treats the orchestrator as not
      configured and the screen will say so. This is a consistent state, not
      a failure -- set the key (openssl rand -hex 32) when you want pipelines.
{{- end }}

      password.
{{- end }}
